# 의정의 흐름 웹

정치에 관심 있는 사용자가 인물·법안·이슈의 변화를 짧게 읽고 공식 근거를 확인하는 Next.js 웹입니다. 실제 기록을 조회하며 API 장애·기록 없음·자료 미공개를 구분합니다. 운영 데이터로 사용하는 예시 정치 기록은 포함하지 않습니다.

## 실행

Node.js 24 이상을 사용합니다. 의존성은 공식 npm에서 확인한 Next.js 16.4.0, React 19.3.0으로 고정했고 lockfile을 함께 제공합니다.

```sh
cd web
npm ci --ignore-scripts
BACKEND_URL=http://localhost:8080 PUBLIC_BASE_URL=http://localhost:3000 npm run dev
```

백엔드는 `tracking.enabled=true`로 실행하고 MySQL 스키마를 준비해야 합니다. `PUBLIC_BASE_URL`을 백엔드의 `tracking.public-base-url`과 동일한 **브라우저 공개 origin**으로 설정합니다. `BACKEND_URL`은 서버에서만 사용하는 백엔드 origin이며 경로나 사용자 정보를 포함하지 않습니다. 공개 환경에서는 HTTPS를 사용합니다. `.env.example`은 설정 이름만 안내하며 실제 비밀은 포함하지 않습니다.

```sh
npm test
npm run typecheck
NEXT_TELEMETRY_DISABLED=1 npm run build
npm run test:smoke
npm start
```

## 기능과 API

- `/`: 주제·행동 필터, 커서 방식의 최신 변화, 관심 대상별 최근 20건을 합친 피드. 관심 피드가 일부 실패하면 부분 결과임을 표시합니다.
- `/activities/[id]`: 짧은 설명, 발표·의결·시행 구분, 원문 발췌·위치·버전, 관련 법안·인물, 개별 표결. `?version=...`으로 불변 기록 버전을 열 수 있고, 공개된 정정 이력과 사유에서 이전 버전으로 이동할 수 있습니다. 변화 공개 시점과 실제 사건·원문 공개 시점은 구분합니다.
- `/people`, `/bills`, `/issues`와 각 상세 페이지: 서버 렌더링 및 제목·설명 메타데이터.
- `/people/[id]`: 검수된 인물 소개 사실·직위 이력·관련 이슈와 역할별 활동을 추가합니다. 이름만 등장한 문서는 개인 활동에 포함하지 않습니다. 인물 ID와 관심 저장 형식은 유지합니다.
- `/people?query=...&organizationId=...&cursor=...`: 공개 승인된 전국 명부를 40명씩 커서로 탐색하고, 검색·기관 필터와 각 인물의 자료 확인일을 보존합니다. 명부 확보와 상세 활동 확보를 구분합니다. 추가 명부 API가 꺼져 있을 때 첫 페이지는 기존 공개 명부를 유지하며, 장애나 커서 실패를 기존 목록으로 감추지 않습니다.
- `/explore?rootKind=person&rootId=...&depth=1`: 인물·기관·법안·정책·사건·문서·이슈의 확인된 관계를 직접 또는 두 단계로 탐색합니다. 지도에서 다음 대상을 선택하거나 같은 노드·간선 목록에서 상세 문서와 근거를 열 수 있습니다. 직위 기간·확인일과 결과 한도를 표시하며, 기관·정책은 그 지점에서 연결 탐색을 이어갑니다. 인물·법안·이슈·사건 상세에서 탐색 페이지로 연결됩니다.
- `/activities/[id]`: 추가 연결 정보가 공개된 경우 대표발의·공동발의·발언·표결 참여·참여 예정과 당시 직위·소속, 고정된 문서·근거 링크를 보여줍니다.
- `/bills/[id]`: 근거가 확인된 원안·대안 연결을 별개 법안으로 표시하고 각 법안 조회에서 확인한 제목·처리 상태를 보여줍니다. 요약 조회는 중복을 제거해 최대 20개, 동시에 4개로 제한합니다. 조회 실패·미공개·한도 초과는 식별자와 단계 미확인으로 표시하며 통합 관계에서 통과 여부·조항별 기여·정책 전체의 공로를 추정하지 않습니다.
- `/issues/[id]?cursor=...`: 검수된 사건 타임라인과 커서 이동을 제공합니다. 발생일을 확인한 기록은 발생일, 나머지는 공개일 기준임을 표시합니다.
- `/documents/[id]?version=...&extractionVersion=...`, `/evidence/[id]`: 원문·추출 버전과 구간을 고정한 문서·발췌·앞뒤 문맥을 제공합니다. 검수된 이름만 공통 인물 페이지로 연결하고, 미확인·겹친·맞지 않는 범위는 원래 텍스트로 표시합니다. 이미지나 임의 HTML을 실행하지 않습니다.
- `/search`: 공개 기록 검색과 커서 이동. `/coverage`: 현재 자료 범위와 수집 상태.
- `/interests`: 최대 20개 관심 대상, 로그인 요청, 계정의 일간·주간·중단 설정.
- `/auth/verify?token=...`, `/unsubscribe?token=...`: 주소에서 토큰을 제거하고 사용자가 버튼을 눌러 확인합니다. 페이지 열람만으로 로그인·알림 해지를 수행하지 않습니다.
- `/about`, `/research`: 편집·정정 원칙과 구독 검증 가설. 결제 기능은 없습니다.

브라우저의 `/api/v1/*` 요청은 제한된 경로·메서드만 고정 `BACKEND_URL`로 전달합니다. 운영·관리 API는 프록시하지 않으며 관리자 키를 웹에 주입하지 않습니다. 변경 요청의 origin을 검증하고 서버의 HttpOnly 세션 쿠키와 CSRF 헤더를 전달합니다. 서버 렌더링은 공개 조회에만 사용합니다.

추가 공개 조회는 `/people/{id}/profile`, `/activities/{id}/context`, `/bills/{id}/lineage`, `/issues/{id}/timeline`, `/documents/{id}`, `/evidence/{id}`입니다. 문서 조회의 `version`과 `extractionVersion`, 사건 연결 조회의 `version`을 응답과 대조합니다. 인물 이름 위치는 Unicode code point 기준 `[start,end)`로 처리합니다. 국회·정부·입법센터·국회도서관·주무부처의 공식 HTTPS 원문만 외부 출처 링크로 표시합니다. 승인되지 않은 관계와 본문 재이용 조건을 확인하지 못한 문서 텍스트는 공개 응답에서 거부합니다.

그래프·전국 명부는 `GET /api/v1/knowledge/graph`, `GET /api/v1/knowledge/people`을 사용합니다. 공개 그래프는 `visibility=published`만 허용합니다. 중복 노드·간선, 없는 노드를 가리키는 연결, 근거 없는 간선, 외부 또는 다른 인물로 이동하는 주소, 내부 저장 경로를 포함한 응답은 거부합니다. 그래프는 최대 100개 노드·1000개 간선으로 검증하며 화면은 40개 노드를 요청합니다. 후보 그래프와 관리자 경로는 웹 프록시의 허용 목록에 포함하지 않습니다.

추가 기능은 백엔드의 `knowledge.enabled=false`가 기본입니다. 추가 조회가 404이면 기존 인물·사건·법안·이슈 화면을 유지합니다. 서버 장애·응답 오류는 별도 안내하며 관련 기록이 없는 것으로 처리하지 않습니다. 백엔드가 허용한 본문 구간만 화면에 표시하고 내부 원문 저장 경로는 공개하지 않습니다.

브라우저 저장소에는 **익명 관심 ID와 알림 선호만** 저장합니다. 인증 토큰·쿠키·CSRF 토큰은 저장하지 않습니다. 인증한 목록은 계정 API로 저장합니다. 로그인 전에 저장한 기기의 목록은 자동 업로드하지 않고, 사용자가 가져오기 버튼을 눌러 계정에 합칠 수 있습니다. 미확인 표결을 불참으로 추론하거나 발표를 검증된 정책 효과로 표시하지 않습니다.

선택 설정 `FEEDBACK_EMAIL`을 넣으면 기록 오류 제보가 사용자 메일 앱의 작성 화면을 엽니다. 메일을 자동 전송하지 않습니다. 실제 로그인·알림 전송은 백엔드의 발송 공급자 설정이 필요하며 웹의 요청 성공은 발송 완료를 의미하지 않습니다.

## 컨테이너

```sh
docker build -t parliament-web .
docker run --rm -p 3000:3000 \
  -e BACKEND_URL=http://backend:8080 \
  -e PUBLIC_BASE_URL=https://your-site.example \
  parliament-web
```

Docker는 standalone 빌드와 static 파일을 복사하고 비특권 사용자로 실행합니다. `BACKEND_URL`, `PUBLIC_BASE_URL`, `FEEDBACK_EMAIL`은 실행 시 설정할 수 있습니다. 컨테이너 안의 `localhost`는 백엔드 컨테이너를 가리키지 않습니다.

## 검증 범위와 남은 운영 작업

단위·렌더링 테스트는 출처 경계, 투표 상태, 장애·부분 결과, 관심 저장, CSRF, 이메일 요청과 수신 중단의 사용자 확인을 검증합니다. 실제 SMTP/SES 발송, 실제 원천 자료의 검수, 운영 인프라 구축, 백업·복원·부하 검증, 사용자 조사와 유료 구매 검증은 별도로 진행해야 합니다. 정치를 자주 보는 사용자가 근거를 확인할 수 있도록 기본 사실과 원문 링크는 무료로 유지합니다.

## 최소 집계 지표

로그인한 사용자가 관심을 저장하거나 등록한 관심 대상과 관련된 실제 기록 상세를 열 때, 선택적으로 `POST /api/v1/usage`에 `follow_saved`, `activity_opened` 집계 이벤트만 전달합니다. 관련성 평가를 직접 누르면 `relevance`와 평가값을 전달합니다. 인물·주제·법안·기록 ID, URL, 본문은 집계 요청에 포함하지 않습니다. 인물·법안·주제 ID로 관련성을 확인하고 이슈 관심은 공개 이슈 정의의 주제도 확인합니다. 이 정의를 불러오지 못하면 관련성을 추정해 집계하지 않습니다. 실패는 기록 열람이나 설정 저장을 막지 않습니다. 익명 사용자의 지표는 서버에 전송하지 않습니다.

`npm start`는 준비된 standalone 출력을 루프백 주소에 바인딩합니다. 컨테이너 밖에서 접근해야 하는 개발 환경에만 `WEB_HOST=0.0.0.0`을 지정하세요. Docker 기본 실행은 컨테이너 내부의 `0.0.0.0`에 바인딩합니다.

## 로컬 모바일·키보드 확인

독립 시험 DB의 백엔드를 `tracking.enabled=true`, `knowledge.enabled=true`로 실행하고 운영자가 검수·공개한 자료 묶음을 준비합니다. 이메일 발송은 사용하지 않습니다. 아래 예시에서는 백엔드 포트를 18080, 웹 포트를 13000으로 사용합니다. 백엔드 공개 origin도 `http://127.0.0.1:13000`으로 맞춥니다.

```sh
BACKEND_URL=http://127.0.0.1:18080 \
PUBLIC_BASE_URL=http://127.0.0.1:13000 \
WEB_HOST=127.0.0.1 PORT=13000 npm start
```

브라우저의 반응형 화면을 360×800으로 설정하고 `/issues/child-support-advance`에서 사건→근거→문서 속 이름→인물→법안·대안으로 이동합니다. 자료가 공개되지 않았다면 실제 공개된 ID로 확인하며 예시 데이터를 제품 응답에 넣지 않습니다. 긴 제목·원문 버전·본문이 가로로 넘치지 않는지, `Tab`·`Shift+Tab`으로 이름·근거·관심 버튼·역할 선택에 접근할 수 있는지, `Enter`로 링크를 열고 선택 컨트롤로 역할을 바꿀 수 있는지 확인합니다. 추가 기능 404와 서버 장애는 SSR 통합 검사에서 각각 검증합니다.

관계 탐색에서는 연결 깊이·종류 선택→노드의 이어 보기→근거→원문 버전 순서로 이동합니다. 지도는 내부에서 스크롤하며, 360px에서 아래 노드·간선 목록의 링크를 키보드로 사용할 수 있습니다. 전국 명부의 다음 커서에서도 검색·기관 필터가 유지되는지 확인합니다. 계약용 가상 기록은 `tests/smoke.test.mjs`의 독립 서버에만 존재하며 공개 제품에는 적재하지 않습니다.
